# 33커밋 체크포인트와 연구 작업 범위

커밋 번호와 IN 작업 번호는 일치하지 않는다. 초기 저장소 생성 커밋을 제외한
연구 커밋을 센다. 33커밋은 IN-033 또는 페이즈 4 완료를 뜻하지 않는다.
코어·명세·KAT는 이 구간에서 바꾸지 않았다. 보안 강도·독창성은 미확정이다.

| 페이즈 | 계획 작업 | 현재 확보한 근거 | 남은 핵심 과제 |
|---|---|---|---|
| 1 | IN-001~008 | 단일 명세, 순차 갱신, 역변환, SHAKE 인코딩 | 선행 설계와 동치·독창성 조사 심화 |

| 3 | IN-018~024 | FS 노출, DDT/LAT, FM 국소 편향, 유지 결정 | 국소 위험의 전체 공격 연결과 재설계 판단 |

## 재현

```sh
make all check research
python3 -m pip install -r research/requirements-smt.txt
make smt-check smt-research
```

SMT는 선택적 연구 의존성이며 C 라이브러리 의존성이 아니다.
`make smt-research`는 7개 실험을 새로 실행해 `build/smt_summary.json`을 만든다.
각 하위 프로세스는 60초, 합산 오라클 예산은 1048576블록이며 협력적 전체
실행 예산은 180초다. 이 숫자는 solver 단일 질의 timeout과 별개다.
소스·바이너리·solver 버전이 섞이거나 원장이 맞지 않으면 중단한다.
실패 시 이전 summary를 재사용하지 않는다. JSON과 SMT2는 CI artifact에서
7일간 제공하며 저장소에는 생성 결과를 커밋하지 않는다.

이 환경의 전체 SMT 실행은 107블록 평가, 7보고서, 약 28초였다.
SAT 8·UNSAT 11·UNKNOWN 19에는 알려진 정답의 대조 질의도 섞여 있다.
숫자를 공격 성공 수나 안전성 통과 수로 읽지 않는다. 시간·solver 결정은
실행 환경에서 달라질 수 있으며 현재 artifact의 개별 질의가 기준이다.
기존 `make research`의 9실험·8251624블록 집계와 별도 묶음이다.

## 유지 결정과 외부 검토 질문

현재 결정은 **연구용 코어 유지, 최적화·실사용 안전성 승인 보류**다.
1라운드 FS 64비트 복원과 FM의 국소 편향은 알려진 위험이다.
FM 복원과 고라운드 탐색의 UNKNOWN은 위험 해소 근거가 아니다.

외부 검토에서는 다음을 우선 확인한다.

- FS 노출과 FM의 비전단사 구조가 여러 라운드 키 복원으로 연결되는가?
- 보장 support가 사라진 뒤에도 여러 비트 결합 차분·선형 hull이 남는가?
- 알려진 마스터키 아래 한 경로의 존재를 넘어, 미지 키 오라클에서
  측정 가능한 데이터·시간·메모리 이득이 있는가?
- 전체 28라운드에 대한 가장 좋은 공격과 라운드 여유를 정량화할 수 있는가?

실용적인 고라운드 공격 또는 보안 여유 부족이 확인되면 명세·코어·KAT를
함께 재설계하고 기존 분석을 무효화한 뒤 다시 검증한다.

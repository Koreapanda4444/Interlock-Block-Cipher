# Interlock 추가 공격 분석

이 문서는 현재 단일 코어를 대상으로 한 18커밋 이후의 근거를 정리한다.
규범 수식은 `spec_ko.md`, 전체 위험과 결정은 `security_ko.md`를 따른다.
명세·코어·KAT는 변경하지 않았으며 새로운 평문 오라클 분석과 내부 부품
관측 모델을 구분한다. 분석 스크립트의 종료 성공은 보안성 합격이 아니다.

## FS의 부호 있는 선형 상관

`research/linear.py`는 L의 전치 `L^T(x)=x xor ROR(x,3) xor ROR(x,17)`를
32×32 기저 내적으로 확인하고 `(L^T)^-1=(L^T)^31`을 검사한다.
균등 32비트 입력, 고정 서브키 k에 대한 FS의 상관은 정확히
`(-1)^<alpha,k> * product_i LAT[alpha_i,(L^T beta)_i]/16`이다.
니블별 독립성과 입력 XOR 키의 위상 변화로 얻으며, 라운드 간 독립 가정은 없다.
4개 키·8개 활성 니블·225개 비영 마스크 쌍의 7200개 상관을 C FS 출력과
전수 대조한다. 부호와 상관/편향(상관의 절반)을 구분해 저장한다.
`python3 research/linear.py`로 재현한다.

## 외부 블록 오라클의 선형 구별식

1라운드의 두 번째 출력 단어는 `ROL(a xor FS(b,k0),13)`이다.
FS의 마스크 alpha,beta를 선택하면 평문 마스크 `(beta,alpha,0,0)`와
암호문 마스크 `(0,ROL(beta,13),0,0)`의 상관은 FS 상관과 정확히 같다.
LAT 절댓값 8인 한 니블 마스크를 사용하면 모든 키에서 절댓값 1/2이며
위상만 k0에 의존한다. 훈련 평문으로 위상을 추정하고 겹치지 않는 검증
평문으로 부호·상관·편향을 기록한다. 공격 자체는 내부 키를 읽지 않는다.
실험의 정답 대조에만 실제 키 스케줄을 사용한다.
`python3 research/linear.py --cipher`는 고정한 동일 마스크를 1~8라운드에서
측정한다. 2라운드 이상의 수치는 관측이며 선형 hull의 상계가 아니다.

## S-box boomerang 연결표

`research/boomerang.py`는 현재 C의 4비트 치환에 대해 BCT를 전수 계산한다.
역치환으로 정의한 식과, `(S(x) xor S(y)) = (S(x xor a) xor S(y xor a)) = b`
를 만족하는 순서쌍을 세는 독립 정의의 256개 항목이 일치해야 한다.
자명 축·DDT 해의 포함·짝수성도 확인한다.
[Cid 등](https://eprint.iacr.org/2018/161)의 BCT는 라운드 사이 switch의
의존성을 다루는 부품 도구이며, 이 표를 단순히 곱해 전체 암호의 확률을
계산하지 않는다. `python3 research/boomerang.py`로 재현한다.

## 외부 boomerang quartet

`python3 research/boomerang.py --cipher`는 P,P xor alpha를 암호화하고
각 결과에 beta를 XOR한 후 역오라클을 호출한다. 반환 평문 차분이 alpha인지
검사하며 quartet당 정방향 2·역방향 2쿼리를 모두 센다. 두 암호문이 단순히
서로 교환되는 자명 성공은 따로 기록한다. 3개 키·4개 마스크·1~8라운드를 검사한다.
1라운드에서 alpha가 a에만, beta가 세 번째 출력 단어에만 있으면 모든 키에서
성공한다. 역변환 시 원래 d에 같은 차이가 생기고 b는 그대로, c의 변화는
두 실행에서 같으며 a 차분은 보존되기 때문이다. r=0 항등 대조와 이 보장
관계를 자동 검증한다. 다른 행의 성공 횟수는 표본 관측이며 독립 trail 곱이나
전체 라운드 공격 성공률로 바꾸지 않는다.

## 역방향 support와 불가능 차분

`python3 research/support.py --inverse`는 실제 역갱신 순서와 역회전을 사용해
첫 r라운드의 역순열을 분석한다. 128개 단일비트 입력 차분을 r=1~8에서
전파하고 고정 비트가 있는 경우 그것을 위반하는 비영 출력 차분을 생성한다.
그 출력은 보수적 support 증명에 의해 불가능하다. 미확정 비트의 가능한
조합 전체가 실제 도달한다는 주장은 하지 않는다. 4키·각 조건 16쌍을 실제
C 역오라클로 대조하고 역방향 ledger를 별도로 남긴다.

## 제한된 ANF와 FM 충돌

`python3 research/algebra.py`는 고정 키와 고정 상위/하위 비트에서 16변수
입력 큐브를 전수 계산하고 Möbius 변환으로 좌표별 ANF 차수를 구한다.
변환을 두 번 적용해 원래 진리표로 돌아오는지 검사한다. 제한 함수 차수는
전체 함수 차수의 하한이며 정확한 전체 32변수 차수라고 부르지 않는다.
FS의 최대 차수 3은 별도 부품 정리와 대조한다.

서브키 0의 FM에는 `11111111`, `66666666`의 충돌이 있다. S 적용 뒤
`55555555`, `aaaaaaaa`가 되고, 7비트 회전이 두 값을 교환하여 둘의
`y+ROL(y,7)`이 모두 ffffffff이기 때문이다. C에서 재현한다. 라운드 함수는
전단사일 필요가 없고 이 서브키를 갖는 마스터키를 찾은 것도 아니므로,
충돌만으로 전체 블록 암호가 깨졌다고 판단하지 않는다.

## 실제 마스터키의 XOR 관계

`python3 research/keys.py`는 4개 기준 키의 256개 단일비트 XOR 관련 키를
실제 SHAKE 스케줄로 확장한다. 모든 1028번 확장을 Python hashlib 기반
계산과 대조하고, 전체 스케줄 중복·동일 서브키·0인 FM 서브키와 Hamming
거리를 기록한다. 56바이트 인코딩의 단사성과 SHAKE 출력 충돌 부재는 별개의
주장이다. 이 표본에서 충돌이 없다는 결과나 avalanche 수치를 관련 키 안전성
증명으로 취급하지 않는다. 내부 키 준비 감사이므로 외부 블록 쿼리 수는 0이다.

## 1라운드 외부 쌍에서 두 서브키 복원

`research/recovery.py`의 복원 함수는 평문·암호문 한 쌍만 받는다.
`A=ROR(C_b,13)`, `D=ROR(C_c,21)`, `G=L∘S`라 하면
`k0=b xor G^-1(a xor A)`, `k3=A xor G^-1(d xor D)`이다.
따라서 1라운드에서 내부 관측 없이도 두 FS 서브키 64비트를 계산할 수 있다.
64개 마스터키에서 이를 재현하고 키마다 새 16블록의 두 출력 단어를 예측한다.
실험 정답 비교에만 컨텍스트를 읽고 복원 함수에는 전달하지 않는다.
이는 전체 256비트 마스터키 또는 FM 서브키 복구, 2라운드 이상 공격이 아니다.
`python3 research/recovery.py`로 재현한다.

## carry를 생략하지 않는 SMT 부품 모델

`research/smt.py`는 C의 비트평면 구현과 별도로 4비트 표를 사용하는
정확한 32비트 QF_BV 식을 작성한다. 덧셈은 bit-vector mod 2^32이고,
회전·AND·S-box·L의 순서를 그대로 반영한다. 경계값과 고정 seed 입력에서
FS/FM 결과를 C 코어와 대조한다. 확률을 독립으로 곱하는 차분 근사가 아니다.
[Z3 저자 문서](https://z3prover.github.io/papers/programmingz3.html)를 기준으로
SAT·UNSAT·UNKNOWN을 구분한다. 기본 C/stdlib 연구와 분리한 선택 의존성은
`python3 -m pip install -r research/requirements-smt.txt`로 설치하고
`make smt-check`로 검증한다. CI에서도 별도 job에서 실제 실행한다.

## 전체 연결의 SMT 일치성

순차 갱신·마지막 동시 순열·역갱신을 별도 bit-vector 식으로 연결한다.
세 KAT 입력에서 1~28라운드의 84개 C prefix 및 각 역변환을 대조한다.
또한 고정 평문에 대한 전체 28라운드 식의 SAT 해가 C 출력과 같고,
틀린 출력을 요구하면 UNSAT인지 확인한다. 이 UNSAT는 특정 고정 입력의
일치성 검사이며 공격이나 전체 보안성 증명이 아니다.
solver의 논리·버전·제약 지문·제한·실측 시간·UNKNOWN 사유를 기록한다.

## 두 실행의 정확한 차분 제약

`python3 research/smt.py --pairs`는 실제 마스터키에서 유도한 서브키를
고정하고 P, P xor delta의 두 실행을 별도 연결한다. 낮은 8비트만 변하는
256개 평문 영역에서 지정 출력 차분 비트의 가능성을 묻는다. r=0 SAT와
r=1의 알려진 불가능 비트 UNSAT를 대조한다. SAT 모델의 평문은 C로 다시
암호화해 목표 비트가 맞는지 확인하며, 모델식도 `build/smt_pair_*.smt2`에
남긴다. 다른 라운드의 UNKNOWN은 실패한 탐색으로 기록한다. 이는 고정 키·
제한 영역의 가능성 검사이며 전체 차분 확률이나 알 수 없는 마스터키 공격이 아니다.

## SMT 모델의 누락·거짓 양성 검사

`python3 research/smt.py --count`는 FM의 8개 입력 자유 비트만을 투영해
조건을 만족하는 평문을 하나씩 차단하며 센다. 내부 보조 변수의 다른 할당을
새 평문으로 세지 않는다. 별도 C 전수 계산의 해 집합과 비교하여 거짓 양성·
중복을 즉시 거부하고, 종료 UNSAT일 때 누락도 없음을 확인한다. 제한에 걸리면
완료했다고 표시하지 않고 해 개수 하한·상한과 UNKNOWN 사유를 남긴다.
CI는 더 작은 4비트 영역의 완전 열거를 필수로 검사한다. 이 확률은 지정된
affine 부분 영역의 정확한 값이며 전체 32비트 입력의 확률이 아니다.

## 128비트 평문 영역의 축소라운드 탐색

`python3 research/smt.py --search`는 실제 한 마스터키와 입력 차분을 고정하고
128비트 전체 평문을 자유 변수로 둔다. 보장 support가 있는 라운드는 그것을
위반하는 해를, 그 외는 지정한 출력 비트 차분을 만족하는 해를 찾는다.
1~8라운드 각각 timeout 1000ms·rlimit 300000을 적용하고 결과를 구분한다.
SAT이면 입력·출력뿐 아니라 모든 중간 라운드의 두 상태를 C prefix로 다시
계산한다. 재현한 경로 한 개는 특정 평문쌍의 차분 궤적이며, 높은 확률의
characteristic이나 differential hull을 찾았다는 뜻은 아니다.
고정 키의 UNSAT 검사는 별도로 증명한 모든 키의 support 정리를 대신하지 않는다.

## 외부 1라운드 FM 서브키 제약

`python3 research/smt.py --recover`는 평문·암호문에서
`C=ROR(out_a,5)`, `B=ROR(out_d,27)`를 계산한다.
따라서 `FM(d,k1)=c xor C`, `FM(C,k2)=b xor B`의 식을 얻는다.
공격자는 FM 내부 상태나 정답 서브키를 읽지 않는다. 슬롯별 32비트 미지 키를
두 발견 쌍으로 제약하고 남은 세 쌍은 solver에 넣지 않는 검증용으로 둔다.
SAT 후보가 나오면 C 부품으로 발견 쌍과 검증 쌍을 대조한 뒤에만 정답 키와
비교한다. 후보를 차단한 후 UNSAT여야 발견 식에 대한 유일성이 성립한다.

3개 마스터키·두 FM 슬롯, 총 15개 외부 블록 쿼리다. 각 질의의 제한은
1000ms·rlimit 300000이며 관측한 여섯 질의는 모두 UNKNOWN이었다.
정답을 고정한 별도 SAT 대조는 모델 연결 확인이며 키 복원 성공이 아니다.
FS의 닫힌식 복원과 달리 FM 복원 성공·유일성·마스터키 역산은 미해결이다.

## 12~28라운드의 계산 한계

`python3 research/smt.py --full`은 영 마스터키에서 delta=1 또는 2^127로
두 실행을 연결한다. 128비트 평문 전체를 자유 변수로 두고 출력 XOR 차분의
Hamming 무게가 8 이하인지 묻는다. 128개 비트를 8비트 unsigned 합으로
세므로 최대 128까지 overflow 없이 표현한다. 12·20·28라운드의 6개 식에
각각 1000ms·rlimit 300000을 적용한다. 식 생성 시간은 solver 시간과 별개이며
보고서의 전체 wall time에 포함된다. SMT2와 질의 지문도 남긴다.

관측 실행은 모두 UNKNOWN이었다. SAT가 나오면 모든 라운드의 두 상태와
최종 무게를 C로 재검증하도록 구현했다. 한 개 경로가 발견되어도 그것은
알려진 고정 키 아래의 실행 가능성일 뿐 높은 확률의 characteristic이나
미지 키 공격이 아니다. UNSAT라도 지정 키·차분·무게 조건에 한정되며,
UNKNOWN으로 전체 라운드 안전성을 주장하지 않는다. IN-036의 최적 확률
탐색·IN-037/038의 hull 상계는 아직 미해결이다.

## 일관된 SMT 결과 묶음

`make smt-research`는 부품·연결·평문쌍·투영 계수·축소 탐색·FM 복원·고라운드
탐색의 7개 보고서를 새로 생성한다. 소스·바이너리 지문과 쿼리 원장, full 모드,
solver 버전을 검증하고 고라운드 SMT2의 지문을 보고서와 대조한다.
UNKNOWN 사유·자원 제한 누락 및 안전성을 뜻하는 임의 solver 상태를 거부하는
부정 회귀도 `make smt-check`에 포함한다. CI는 두 target을 실제 실행한다.
SAT/UNSAT/UNKNOWN 집계에는 대조 실험도 포함하며 보안 합격 수가 아니다.

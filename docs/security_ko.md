# Interlock-128 연구 기록

## 범위와 공격 모델

목표는 고정 비밀키 `k`에서 128비트 순열 `E_k`와 역순열 `D_k`를
정의하고 암호분석하는 것이다. 256비트 키는 안전성 256비트를 뜻하지 않는다.

| 모델 | 실제 세계 오라클 | 이상 세계 | 성공 기준 |
|---|---|---|---|
| PRP / 선택 평문 | 적응적 `E_k(x)` | 균등 128비트 순열 `P(x)` | 두 세계 판별 확률 차이 |
| 강한 PRP / 선택 암호문 포함 | `E_k(x)`, `D_k(y)` | 같은 `P` 및 `P^-1` | 두 세계 판별 확률 차이 |
| 키 복구 | 위에서 정한 외부 오라클 | 해당 없음 | 숨긴 키를 복원하고 미사용 쌍으로 확인 |
| 관련 키 | 정해 둔 XOR 차이 `delta`의 `E_(k xor delta)` 및 필요시 역순열 | 키 관계를 명시한 비교 실험 | 비용·성공률·허용 키 관계를 함께 기록 |
| 내부 관측 | 선택한 FS/FM의 실제 입출력 또는 중간상태 | 전체 블록 오라클과 구분 | 해당 서브키 등 관측 모델 안에서만 성공 판단 |

PRP는 암호화 함수만, 강한 PRP는 역함수 접근까지 허용한다.
원시 결정적 블록 함수는 IND-CPA/IND-CCA 암호화 방식이 아니다.
동일 블록의 동일 암호문, 무결성 부재, 메시지 길이 처리 미제공을 전제로 한다.
패딩, 모드, 인증, 네트워크나 파일 입출력은 만들지 않는다.

실험에는 쿼리 수 `q`, 시간, 메모리, 성공률, seed, 키 샘플과 검정 대상을
기록한다. `q(q-1)/2^129`는 균등 **복원추출 값**의 충돌 근사이며
순열이 서로 다른 입력을 서로 다른 출력으로 보내는 성질과 혼동하지 않는다.
`2^64` 부근의 birthday 규모는 여러 모드/환원에서 중요하지만 이 원시 함수의
보편적 실사용 허용량이나 안전한 데이터 한도를 인증하는 수치가 아니다.
현재 실제 비밀 보호에 허용된 데이터량은 정의하지 않는다.

## 미검증 주장과 반증 가능한 가설

SHAKE256 코드는 FIPS 202와 Keccak 저자의 수식에서 작성했다. 외부 소스 코드를
복사하지 않았고 별도 런타임 라이브러리에 의존하지 않는다. 표준 KAT는
[NIST Msg0](https://csrc.nist.gov/csrc/media/projects/cryptographic-standards-and-guidelines/documents/examples/shake256_msg0.pdf)와
[Msg1600](https://csrc.nist.gov/csrc/media/projects/cryptographic-standards-and-guidelines/documents/examples/shake256_msg1600.pdf)의
첫 512 출력 비트이며 Interlock의 자체 KAT와 구분한다.

| 항목 | 확인할 조건 | 현재 상태 / 실패 시 조치 |
|---|---|---|
| 명세와 C 구현이 일치 | 독립 계산한 키·각 라운드·블록 KAT | 고정 4개 KAT 및 644개 전체 키/trace 대조 통과 |
| 매 라운드가 순열 | 역갱신 증명과 독립 역변환 대조 | 아래 증명 및 각 라운드 역변환 대조 |
| L이 전단사 | GF(2) 증명과 32차원 rank 검사 | 아래 증명; `make research`로 재현 |
| FS 내부 관측으로 서브키 복원 | 역선형층·역치환으로 `k=x xor S^-1(L^-1(y))` | 현재 C 함수 대상으로 재현; 외부 전체 암호 공격 아님 |
| FM이 이전 함수보다 개선 | 동일 조건의 비교 및 차분 경로 분석 | 미입증; 과거 코어를 저장소에 복제하지 않음 |
| 4라운드에서 과거 편향이 줄어듦 | 새 독립 표본, 사전 지정 통계량과 다중검정 | 과거 원시 데이터·조건이 없어 승계 불가 |
| 28라운드에 충분한 여유 | carry 포함 trail/hull, 적분·대수·MITM 등 | 미탐색, 공격 발견 시 최적화/릴리스 중단 |
| 관련 키·동치 키·약한 키 부재 | 명확한 오라클과 비용 제한 하 탐색 | 미검증; SHAKE 사용만으로 주장 불가 |
| 비밀 의존 타이밍/메모리 누출 부재 | 테이블 없는 소스, 생성 코드와 플랫폼 측정 | 소스 규칙만으로 보증 불가 |
| 기존 암호와 비동치·독창적 | 선행 연구 조사와 동치 변환 분석 | 미확정 |

근거는 증명, 작은 영역 전수검사, 재현 공격, 통계적 관측, 미해결의
다섯 종류로 나눠 기록한다. 시간초과·미탐색·KAT 통과는 보안 증명이 아니다.
알려진 전체 라운드 공격이 발견되면 현재 명세·코어·KAT를 함께 수정하고
기존 분석의 적용 여부부터 다시 확인한다.

## 라운드 가역성: 증명

서로 다른 단어 `u,v`에 대한 `u <- u xor F(v,k)`는 적용 중 `v`가
변하지 않으므로 자기 역변환이다. 키를 고정하면 F가 비전단사여도 성립한다.
라운드는 이런 갱신 네 개를 `a,c,b,d` 순서로 합성한 뒤, 가역 회전과
네 단어 순열을 합성한 것이다. 마지막 출력 순열을 먼저 풀면 순차 갱신
직후의 `(a',b',c',d')`가 복구된다. `d,b,c,a` 역순 갱신에서 각각 필요한
`a',c',d,b`를 사용할 수 있으므로 원래 네 단어를 정확히 복원한다.
28개 라운드를 역순 합성하면 고정 키마다 128비트 공간의 순열이다.
이 증명은 순열이라는 성질만 보이며 PRP/강한 PRP 보안성을 보이지 않는다.

## L32와 내부 FS 관측: 증명 및 재현

GF(2) 위에서 왼쪽 1비트 회전 연산을 R이라 쓰면 `R^32=I`,
`L=I+R^3+R^17`이다. 이 세 선형 연산은 교환하므로 특성 2의
Frobenius 항등식에 의해 `L^32=I+R^96+R^544=I+I+I=I`.
따라서 L은 전단사이고 `L^-1=L^31`이다.
`research/analyze.py`는 실제 32개 기저벡터의 rank와 역행렬 항등식을 검사한다.

L의 **비트 branch number** `min(x!=0)(wt(x)+wt(L(x)))`는 정확히 4다.
입력 weight 1의 세 회전 위치가 달라 출력 weight는 3이다. 입력 weight 2는
패리티 보존과 가역성 때문에 출력 weight가 최소 2이고, 입력 weight 3 이상은
출력 weight 최소 1이므로 전체 하한은 4다. 단일비트 입력이 등호를 달성한다.
이는 니블 단위 branch number나 전체 라운드 활성 S-box 하한이 아니다.

`FS(x,k)=L(S(x xor k))`의 정확한 내부 입출력을 한 쌍 알면
`k=x xor S^-1(L^31(FS(x,k)))`를 계산한다. 1024개 고정 seed 표본에서
현재 C FS 함수의 서브키를 이 식으로 복원하는 회귀를 수행한다.
추가 내부 FS 쿼리 한 개의 출력을 예측할 수 있어 FS 자체는 독립 PRF로
가정할 수 없다. 전체 블록 오라클은 이런 입출력을 직접 제공하지 않으며,
이 결과는 256비트 마스터키 복구나 28라운드 외부 공격을 보이지 않는다.

## 1라운드 외부 구별 공격: 증명 및 재현

평문쌍을 `(a,b,c,d)`와 `(a xor 1,b,c,d)`로 정한다. 첫 갱신 후 `a`의
차이는 1이며 `c,b`의 갱신값은 두 실행에서 같다. 따라서 순열 뒤 출력 차분은
LE32 단어로 `(0, 00002000, *, 0)`이다. 세 번째 단어만 제약이 없다.
이 관계는 키와 평문 값에 관계없이 성립하며 암호화 오라클 쿼리 두 개만으로
1라운드를 구별한다. 이상 128비트 순열의 서로 다른 입력쌍은 균등 비영 출력
차분을 가지므로 이 관계의 확률은 정확히 `2^32/(2^128-1)`이다.
실제/이상 세계 수락 확률 차이는 `1 - 2^32/(2^128-1)`이다.
O(1) 시간·메모리, 데이터 2블록인 축소라운드 공격이며 전체 28라운드 공격으로
확장한 결과는 아니다. 현재 C 코어에서 16키 × 64쌍 = 1024회 재현한다.
이 회귀의 seed는 분석 JSON에 별도로 기록한다.

이 세 계열과의 직접 구성 비교는 IN-004의 초기 조사다. 이름이나 상수 조합의
차이는 신규성 증명이 아니며 구조적 동치, 새 공격과 선행 설계의 추가 조사가
필요하다. 표준 부품 SHAKE256의 성질은 현재 블록 결합의 안전성 근거와 분리한다.

## 재현과 통계 해석

`make check`는 표준 SHAKE KAT, 독립 생성한 4개 전체 KAT(각 112개 서브키와
입력/28라운드 상태), API 부정·중첩 시험, 4480개 왕복, Python 독립 대조를
실행한다. Python 대조는 140개 SHAKE 길이 조합, 1060개 FS/FM 입력쌍,
644개 키/블록 전체 trace와 독립 역변환을 검사한다. seed는 `0x494c4f434b`다.
벡터는 테스트 중 자동 수정되지 않는다. 명세 지문이 달라지면 검증이 실패하며
원인을 확인한 뒤 `python3 tests/reference.py --write`로 명시적으로 갱신한다.

`make research`는 현재 C 코어를 호출하는 테스트 전용 reduced-round 하네스다.
공개 정적 라이브러리는 고정 28라운드 API만 포함한다. 네 고정 키(제로·올원·
증가열·seed 생성 키), 입력 차분 LE bit 0 하나, 라운드 1..4에 대해 데이터셋당
8192개의 중복 없는 평문쌍을 검사한다. 출력 차분 비트별 빈도 128개와
독립 균등 비영 차분 대조군을 기록한다. 키별·라운드별 최대 편향을 모두 남겨
좋아 보이는 결과만 고르지 않는다. seed는 `0x494e5445524c4f43`이다.

총 2048개 검사에 대한 alpha=0.01의 Hoeffding/union-bound 기준선은
독립 Bernoulli(1/2) 모델의 비교용이다. 이상 순열의 서로 겹치지 않는 쌍과
대조군의 차이는 birthday order `q^2/2^128`의 근사로 설명하며, 이 수치를
실제 공격 성공 확률이나 엄밀한 전체 순열 보안 한계로 보고하지 않는다.
낮은 라운드의 기준선 초과도 프로그램 실패로 숨기지 않고 결과에 남긴다.
프로그램 exit 0은 검사의 실행 완료이며 보안성 합격이 아니다.
과거 4라운드 실험의 원시 데이터·정확한 조건이 없어 그 실험의 재현 또는
FM의 개선 여부는 주장하지 않는다. 전체 trail/hull, carry 모델과 공격 비용
분석은 남아 있다. 시간·peak RSS·입출력 seed·실제 코어/명세/KAT/하네스와
호출 바이너리의 SHA-256은 미커밋 `build/analysis.json`에 재생성한다.

## 구현 검증 범위

로컬 GCC 13.3.0의 `-O0`, `-O2`, `-O3` 각각에서 `make all check`를
실행해 C 시험과 독립 대조를 통과했다. ASan·UBSan으로 별도 C 실행 파일도
검사했다. 이 실행 환경은 `/proc/.../task` 접근 실패로 LeakSanitizer 시작이
실패하여 로컬 sanitizer 실행에만 `ASAN_OPTIONS=detect_leaks=0`을 사용했다.
따라서 로컬 LSan 검사를 완료했다고 주장하지 않는다.

원격 CI는 GCC·Clang × 최적화 0/2/3의 6개 기능 job, 두 컴파일러의
ASan·UBSan job, 연구 재현 job으로 구성했다. 원격 sanitizer에는 로컬의
LSan 비활성화 설정을 넣지 않는다. 실제 성공 여부는 해당 커밋의
[Actions 실행](https://github.com/Koreapanda4444/Interlock-Block-Cipher/actions)으로
확인하며 workflow 파일의 존재만으로 통과를 주장하지 않는다.
로컬에는 Clang이 없어 그 컴파일러 결과는 원격 실행으로 확인한다.

정적 라이브러리의 심볼을 확인해 시험 전용 `il_test_*`와 가변 라운드 함수가
포함되지 않는 것을 검사했다. 32비트·빅엔디언 타깃 실행, 타이밍 검정과
실제 생성 코드 감사는 아직 수행하지 않았다. 비밀 인덱스 테이블이 없는
소스는 이 플랫폼들에서의 누출 부재나 constant-time 인증을 뜻하지 않는다.
규범 명세와 KAT의 지문이 연구 기록에 실제 존재하는지도 `make check`에서
확인해 문서와 검증 파일의 불일치를 검출한다.

## 추가 연구: 오라클과 자원 계약

9번째 커밋부터는 `research/common.py`의 Session/Oracle을 사용한다.
한 번의 block query는 **블록 한 개에 대한 지정 라운드 순열/역순열 평가**다.
배치 호출 한 번을 쿼리 한 개로 세지 않으며 순방향·역방향·라운드별 ledger를
별도로 남긴다. 역오라클은 첫 r개 라운드 합성의 역함수다. 공개 28라운드
라이브러리와 혼동하지 않으며 마지막 r개 라운드의 역함수도 아니다.

`make research-check`는 0~28개 prefix를 독립 중간값과 대조하고 각각의
역오라클을 검사한다. 블록 길이·라운드·쿼리 예산 거부와 키 소거도 검사한다.
연구 전용 C 배치 함수의 count overflow, NULL, 라운드, 방향 오류는
ASan/UBSan이 적용되는 C 시험에도 포함한다. C 배치의 부분 중첩은 호출자
금지 조건이며 정확한 in-place만 허용한다. Python 래퍼는 별도 출력을 사용한다.

새 실험 JSON은 query budget, 실제 block query 수, seed, 환경, 경과 시간,
peak RSS, 현재 명세·코어·KAT·연구/시험 코드 및 호출 바이너리 지문을 포함한다.
배치 크기는 131072블록 이하이며 시간 예산은 배치 사이의 협력적 중단이다.
예산 초과는 예외로 중단하고 완료 JSON을 쓰지 않는다. 부분 탐색을 보안 통과나
완료 상태로 기록하지 않는다. 재현 가능한 결과만 `build/`에 생성한다.

## 1~3라운드 보장 차분 비트

`research/support.py`는 차분 각 비트를 0, 1, 미확정으로 추상화한다.
PRESENT 치환은 허용 입력 차분의 DDT support를 전수 합집합하고,
XOR·회전·L은 가능한 비트값을 보수적으로 전파한다. FM에는 차분 0이면
출력 차분 0, 그 외에는 모든 32비트 출력 차분을 허용한다. 따라서 FM의
보안성·독립성·Markov 가정 없이도 **고정된 비트 제약은 모든 키·입력에
성립**한다. 비트 사이 상관을 버리므로 미확정값의 실제 도달 가능성은 보이지 않는다.

입력 차분 1에 대한 출력 차분 `D`의 보장 관계 `D & mask = value`는 다음과 같다.
16진수는 128비트 정수이며 바이트 직렬화는 LE다.

| 라운드 | 고정 비트 수 | mask | value |
|---|---|---|---|
| 1 | 119 | fffffffff03ffc7fffffffffffffffff | 00000000002000400000200000000000 |
| 2 | 54 | 00000000f001f00101ffc3ff07ff8ffe | 00000000000000000000000004000800 |
| 3 | 10 | 0000000000000000001f001f00000000 | 00000000000000000000000000000000 |
| 4 | 0 | 00000000000000000000000000000000 | 00000000000000000000000000000000 |

특히 3라운드에서는 출력 단어 b의 비트 0..4,16..20 차분이 항상 0이다.
암호화 쿼리 두 개로 이 조건을 검사하면 실제 순열은 항상 수락하고, 이상
순열은 `(2^118-1)/(2^128-1)` 확률로 수락한다. 시간·메모리는 O(1)이며
마스터키 복구는 아니다. 이는 앞의 2~3라운드 단순 관측을 넘는 보장된
축소라운드 구별식이다. 전체 28라운드 공격으로 확장했다고 주장하지 않는다.

128개 단일비트 입력 차분 × 1~4라운드의 512개 추상 결과를 계산하고,
4키 × 결과당 16평문쌍 = 32768쌍을 C 오라클 65536쿼리로 대조했다.
4라운드에 고정 비트가 없다는 결과는 이 보수적 모델의 한계이며, 차분 공격이나
다른 불변량이 없다는 증거가 아니다. `make research-check`로 재현한다.

## FS 전수 분포와 FM 국소 편향

`research/components.py`는 FS의 한 니블 입력 차분 120종을 6개 서브키에서
각 16개 활성 니블 값으로 전수 대조한다. 비활성 니블 차분은 0이고 L은
전단사이므로 출력 차분 분포는 해당 PRESENT DDT 행을 L로 옮긴 정확한
분포다. 이 720개 검사는 내부 부품 모델이며 블록 오라클 실험과 구분한다.

FM에는 단일비트 32종·인접/니블/복합 차분을 합친 51종과 6개 고정

## 단일 덧셈의 carry 정확 모델

`research/addition.py`는 `(x+y) xor ((x xor alpha)+(y xor beta)) = gamma`
(합은 mod 2^n)의 해 개수를 정수로 계산한다. 각 비트에서 두 실행의
carry 쌍 `(c,c')` 네 상태를 유지하고, 허용 입력 비트 `(x_i,y_i)`를
열거하여 출력 차분 비트가 일치하는 전이만 누적한다. 초기 carry는 둘 다
0이고 마지막 carry는 버린다. 독립 균등 x,y의 분모는 `2^(2n)`이며,
y를 알려진 상수로 고정하면 그 비트만 사용하고 분모를 `2^n`으로 바꾼다.
prefix별 가능한 모든 입력이 정확히 한 carry 경로에 대응하므로 중복·누락이 없다.

1~4비트의 모든 입력 차분·출력 차분을 독립 전수 덧셈과 대조하고,
고정 상수 덧셈 및 8비트 고정 관련 피연산자도 대조한다. 32비트 예에서는
`(alpha,beta,gamma)=(1,0,1)`의 독립 피연산자 확률 1/2, LSB 불일치의
확률 0, MSB만 바뀌는 차분 확률 1을 정확한 유리수로 확인한다.

[Lipmaa–Moriai](https://eprint.iacr.org/2001/001)는 모듈러 덧셈의 XOR
차분 연구에 대한 선행 문헌이다. 여기서는 직접 작성한 carry DP를 사용하며
새 알고리즘이라고 주장하지 않는다. 현재 FM의 피연산자에는 같은 y와
회전된 y가 함께 들어가므로 독립 균등 가정을 적용해 확률을 곱하지 않는다.
이 구현은 SAT/SMT/MILP 전체 trail 탐색이 아니며 IN-034/035 완료로
처리하지 않는다. 이후 정확한 제약 모델을 검증할 부품 기준이다.

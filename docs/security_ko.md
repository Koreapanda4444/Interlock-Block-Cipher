# Interlock-128 연구 기록

## 범위와 공격 모델

목표는 고정 비밀키 `k`에서 128비트 순열 `E_k`와 역순열 `D_k`를
정의하고 암호분석하는 것이다. 256비트 키는 안전성 256비트를 뜻하지 않는다.

| 모델 | 실제 세계 오라클 | 이상 세계 | 성공 기준 |
|---|---|---|---|
| PRP / 선택 평문 | 적응적 `E_k(x)` | 균등 128비트 순열 `P(x)` | 두 세계 판별 확률 차이 |
| 강한 PRP / 선택 암호문 포함 | `E_k(x)`, `D_k(y)` | 같은 `P` 및 `P^-1` | 두 세계 판별 확률 차이 |
| 키 복구 | 위에서 정한 외부 오라클 | 해당 없음 | 숨긴 키를 복원하고 미사용 쌍으로 확인 |
| 관련 키 | 정해 둔 XOR 차이 `delta`의 `E_(k xor delta)` 및 필요시 역순열 | 키 관계를 명시한 비교 실험 | 비용·성공률·허용 키 관계를 함께 기록 |
| 내부 관측 | 선택한 FS/FM의 실제 입출력 또는 중간상태 | 전체 블록 오라클과 구분 | 해당 서브키 등 관측 모델 안에서만 성공 판단 |

PRP는 암호화 함수만, 강한 PRP는 역함수 접근까지 허용한다.
원시 결정적 블록 함수는 IND-CPA/IND-CCA 암호화 방식이 아니다.
동일 블록의 동일 암호문, 무결성 부재, 메시지 길이 처리 미제공을 전제로 한다.
패딩, 모드, 인증, 네트워크나 파일 입출력은 만들지 않는다.

실험에는 쿼리 수 `q`, 시간, 메모리, 성공률, seed, 키 샘플과 검정 대상을
기록한다. `q(q-1)/2^129`는 균등 **복원추출 값**의 충돌 근사이며
순열이 서로 다른 입력을 서로 다른 출력으로 보내는 성질과 혼동하지 않는다.
`2^64` 부근의 birthday 규모는 여러 모드/환원에서 중요하지만 이 원시 함수의
보편적 실사용 허용량이나 안전한 데이터 한도를 인증하는 수치가 아니다.
현재 실제 비밀 보호에 허용된 데이터량은 정의하지 않는다.

## 진행과 근거

초기 커밋은 범위, 오라클, 비트 명세와 API 계약을 고정한다.
이후 8개 논리적 커밋 범위에서 기본 연산, SHAKE, 키 스케줄, 암복호화,
독립 중간값 대조, 조기 구조 분석과 CI를 검증한다.
첨부 계획의 IN 번호는 연구 작업 ID이며 Git 커밋 수나 보안 점수가 아니다.

## 미검증 주장과 반증 가능한 가설

SHAKE256 코드는 FIPS 202와 Keccak 저자의 수식에서 작성했다. 외부 소스 코드를
복사하지 않았고 별도 런타임 라이브러리에 의존하지 않는다. 표준 KAT는
[NIST Msg0](https://csrc.nist.gov/csrc/media/projects/cryptographic-standards-and-guidelines/documents/examples/shake256_msg0.pdf)와
[Msg1600](https://csrc.nist.gov/csrc/media/projects/cryptographic-standards-and-guidelines/documents/examples/shake256_msg1600.pdf)의
첫 512 출력 비트이며 Interlock의 자체 KAT와 구분한다.

| 항목 | 확인할 조건 | 현재 상태 / 실패 시 조치 |
|---|---|---|
| 명세와 C 구현이 일치 | 독립 계산한 키·각 라운드·블록 KAT | 구현 전, 불일치 시 수정 |
| 매 라운드가 순열 | 역갱신 증명과 독립 역변환 대조 | 증명·시험 대기 |
| L이 전단사 | GF(2) 증명과 32차원 rank 검사 | 확인 대기 |
| FS 내부 관측으로 서브키 복원 | 역선형층·역치환으로 `k=x xor S^-1(L^-1(y))` | 전체 암호 공격과 구분하여 재현 예정 |
| FM이 이전 함수보다 개선 | 동일 조건의 비교 및 차분 경로 분석 | 미입증; 과거 코어를 저장소에 복제하지 않음 |
| 4라운드에서 과거 편향이 줄어듦 | 새 독립 표본, 사전 지정 통계량과 다중검정 | 과거 원시 데이터·조건이 없어 승계 불가 |
| 28라운드에 충분한 여유 | carry 포함 trail/hull, 적분·대수·MITM 등 | 미탐색, 공격 발견 시 최적화/릴리스 중단 |
| 관련 키·동치 키·약한 키 부재 | 명확한 오라클과 비용 제한 하 탐색 | 미검증; SHAKE 사용만으로 주장 불가 |
| 비밀 의존 타이밍/메모리 누출 부재 | 테이블 없는 소스, 생성 코드와 플랫폼 측정 | 소스 규칙만으로 보증 불가 |
| 기존 암호와 비동치·독창적 | 선행 연구 조사와 동치 변환 분석 | 미확정 |

근거는 증명, 작은 영역 전수검사, 재현 공격, 통계적 관측, 미해결의
다섯 종류로 나눠 기록한다. 시간초과·미탐색·KAT 통과는 보안 증명이 아니다.
알려진 전체 라운드 공격이 발견되면 현재 명세·코어·KAT를 함께 수정하고
기존 분석의 적용 여부부터 다시 확인한다.
